# Team Context

## Purpose
Define how the team prefers to build and structure code.

---

## Development Style

- Clean code required
- Small methods preferred
- Clear naming required

---

## Architecture Preferences

- Business logic in Service classes
- Validation in Form Requests
- Controllers must be thin
- Blade = presentation only

---

## API Preferences

- Use shared response format
- Do not create custom response structures
- Include all error cases

---

## Naming Preferences

- Use descriptive names
- Follow existing project naming
- Avoid abbreviations

---

## Code Review Expectations

- No duplication
- No logic in controllers
- No validation in controllers
- Proper structure required

---

## Testing Preferences

- Test validation
- Test services
- Test APIs

---

## Documentation Expectations

- APIs must be documented
- Postman examples required

---

## Common Mistakes to Avoid

- Writing logic in Blade
- Writing logic in controllers
- Skipping validation layer
- Ignoring response format

---

## Collaboration Rules

- Follow existing patterns
- Do not introduce new structure randomly
- Keep code consistent
